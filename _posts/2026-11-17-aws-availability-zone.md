**가용 영역 (Availability Zones, AZ)**: AZ의 물리적 격리 구조, 네트워킹 특징 및 고가용성(HA)·내결함성 설계 원칙

## 2-1. 가용 영역(AZ)의 개념과 구조

가용 영역: 각 리전 내부는 가용 영역이 존재. 리전은 가용 영역들의 결합체

- **리전 당 보통 3개의 가용 영역을 가지며 최소 3개에서 최대 6개**로 구성됌
- 하나의 가용 영역(AZ) 내의 개별 데이터 센터들은 이중화된 전력(안정성), 네트워크망 (연결성) 으로 이루어져 있음 (AZ 내부 데이터 센터의 갯수는 공개되지 않음)

> **[참고] 이중화된 전력, 네트워킹, 통신 연결성을 갖춘 하나 또는 그 이상의 개별 데이터 센터(들)에 대해서**
>
> 가용 영역 내 개별 데이터 센터들은 이중화된 전력(안정성), 네트워크망 (연결성) 으로 이루어져 있음
{: .prompt-info }

## 2-2. 물리적 격리 구조 및 네트워킹 특징

- 재해 격리: 각각의 가용 영역들은 물리적으로 완전히 떨어져 있습니다.
  - 물리적 재해가 발생하더라도 한 AZ장애가 다른 AZ으로 연쇄 전파되지 않도록 철저히 차단하기 위함
- 초고속 네트워킹 연결: 이렇게 철저히 격리되어 있으면서도, 각 AZ들은 고대역폭 및 극도로 낮은 지연 시간을 제공하는 네트워크**(high bandwidth, ultra-low latency networking)**로 촘촘히 상호 연결되어 하나의 리전을 형성함.

→ 결론적으로 초고속 네트워킹 연결이 각 AZ간 된 이유는 데이터를 각 AZ에 모두 저장해서 하나의 AZ에 대한 의존성을 낮추기 위해서다.

## 2-3. 아키텍트의 설계 원칙: 고가용성(HA)과 내결함성

- **고가용성 (High Availability, HA)** 설계: 자연재해나 사고로 인해 특정 AZ 전체가 작동 불능 상태가 되더라도 서비스가 멈추지 않아야 함. 따라서 Solution Architect는 시스템 설계 시 모든 서버와 데이터베이스를 단 하나의 AZ에 몰아넣지 않고 최소 2개 이상 가용 영역(AZ)에 분산 배포해야 함.
  - 한 AZ가 무너지더라도 격리되어 있는 다른 AZ 서버가 즉시 트래픽을 넘겨받아 정상 작동하므로 무중단 서비스가 가능해짐

> **Q. AZ도 고를 수 있나? Region만 고르는 게 아닌가?**
> - **S3 같은 스토리지**는 리전만 고르면 AWS가 **알아서 여러 AZ에 데이터를 복제**해 주지만,
> - **EC2 가상 서버나 데이터베이스**는 아키텍트가 **직접 가용 영역(AZ)들을 지정하여 수동으로 분산 배치(Multi-AZ)하도록 아키텍처를 설계**해야 고가용성이 달성됩니다
{: .prompt-tip }

## 2-4. Availability Zone 요약

- AZ: 리전은 AZ의 결합체이고, 하나의 리전은 3\~6개의 AZ로 구성됩니다(보통 3개). (AZ 내 데이터센터들은 이중화된 전력(안정성)으로 서로 연결(네트워킹)되어 있으며 갯수는 비공개입니다.)
- 리전 내 AZ들은 서로 물리적으로 완전히 떨어져 있습니다. 이는 물리적 재해로부터 연쇄적인 문제에 대해서 보호합니다. 그러면서도 AZ 간 서로 고대역폭 및 낮은 Latency로 연결되어있어 하나의 리전을 형성합니다(데이터에 대한 AZ의 의존성을 낮추기 위해 각각의 AZ에 모두 저장함).
- 아키텍트는 특정 AZ가 작동 불능 상태가 되더라도 서비스가 유지되도록 모든 서버와 데이터베이스를 하나의 AZ에 몰아넣지 않고 분산 배포해야 합니다.
